# 提示词候选版与词典检索存储方案

后续更新：v8已写入本地生产代码；独立词典集入口已实现。当前需求不需要保留全池所有命中，实际采用集合配置快照和一个新增命中表，具体以 [运行手册](../../../../运行手册.md) 为准。下文保留当时的设计备选，未部署服务器。

日期：2026-09-14。状态：本地设计草案，未替换生产提示词、未运行新标注、未修改数据库或清洗规则。

## 核心建议

提示词负责语义判断；词典负责候选检索；样本集负责选取；标注表负责结果。四者通过 corpus_id 关联。不要把“词典命中”“最终方面标签”“进入训练集”混成一个字段。

完整候选提示词在 [prompt-v8-candidate.txt](prompt-v8-candidate.txt)。建议测试版本名为 aspect-sentiment-zh-v8-candidate-1；每次实质修改递增候选版本，不覆盖历史实验。测试通过后再确定正式版本。暂保留 rust-aspects-v2 的13个方面与三种状态，输出格式和现有校验器兼容。

此前37%/22%的复核结果是规划估计，不是新提示词应追求的目标。它依赖“实质讨论可为neutral”的口径。必须通过独立标注验证，不能调提示词直到比例接近这些数。

## 提示词具体改变

1. **把方面成立与情感极性拆开。** 一次调用内先识别实质讨论，再判断情感；不要求改成两次模型调用。事实、具体问题和设计建议可以是 neutral。
2. **移除标签定义中隐含的评价门槛。** diagnostics_debugging、libraries_frameworks、community 等均允许实质的中性描述，与总规则统一。
3. **补充可核对的肯定例子。** v7 的否定边界很多，但有效技术评价的正例不足。候选版明确保留 PR 作者对自己方案的易用性、维护性、效率评价。
4. **仍然排除机械提及和普通状态。** 不能把所有报错当负面、所有API调用当API设计、所有库Bug当生态质量。参数操作问答与涉及组合/扩展能力的设计问题分开。
5. **保留隐含但有明确影响的情感。** “与生命周期斗争后放弃”“为了获取句柄不得不复制大量代码”等属于负面体验，不必有讨厌之类情绪词。
6. **明确同一句话可支撑多个方面。** 不要求为每个方面有独立句子，但要有各自语义依据。
7. **标题与引用不自动传递观点。** 能明确还原认同命题才采用上下文。对作者明确提出的文档草稿/说明不因位于代码框就完全忽略，同时保留观点归属规则。
8. **状态集合暂不变。** 同一方面正负无主次仍用 neutral；mixed 的单列属于后续体系变化，不混入本轮实验。

完整候选版已将19个合成边界例子嵌入提示词。例子覆盖13方面，并非从保留的500条测试材料直接复制。提示词可能变长，后续可在固定开发集上对比“规则+例子”和精简版，按质量与token开销取舍，不能只凭文本长度选择。

### 测试方式

- 先固定人工标注手册，明确普通API问答、兼容性Bug、社区求助回应等边界。保留不参与调规则的测试部分，按父Issue/PR分组。
- 在相同clean-v1输入、模型与调用参数下比较v7与候选版；暂不同时修改清洗。
- 分别检查方面precision/recall、方面+极性F1、neutral漏成空、普通Bug误标，以及逐方面支持数。
- 对已审计的明确漏标建立开发回归集；这些例子不能再用来证明独立泛化质量。
- 输出继续只有aspect/class。若需要证据片段，另设明确版本的审阅实验格式，不在生产解析中偷偷增加字段。
- 不向模型传入词典命中词、candidate_aspect或检索分数，模型仍判断全部13方面，减少被候选标签引导的风险。

注意：现有llm_annotations按(corpus_id, taxonomy_version, prompt_version, model_name)唯一。不同提示词版本可以并存；同版本重复实验会被当前upsert覆盖。需要重复性测试时，应另存实验请求/响应JSONL及request_id、prompt/input hash、参数、时间，不依靠这一张结果表保留所有尝试。后续若常态化实验再增设attempt表，本轮不必先扩建。

## 词典怎么组织

先用Git管理的JSON文件维护规则，按方面分组，但不能只列正负情感词。每条规则有稳定rule_id、candidate_aspect、规则类型、匹配表达式、适用文本区域和排序权重。

每个方面可包含：

- 主题词/短语：lifetime、borrow checker、compile time、maintainer等，用于扩大召回。
- 表达模式：某主题附近的“理解、等待、响应、限制、比较、改进”等，帮助提高排序质量。
- 别名、拼写变体和必要的中文表达。
- 区域标记：TARGET自然语言、TARGET引用、代码/日志、CONTEXT。不同区域可降权或分开检索，不能把CONTEXT命中当TARGET作者评价。

“情感词与主题词必须同时出现”不作为硬门槛，否则neutral和隐含体验又会漏掉。排序高低也不是情感置信度。短语、正则、词边界的行为随matcher_version冻结，避免用SQL LIKE的偶然行为当词典定义。

第一版优先扫描已有语料。可按主键分批读取并在检索程序中匹配，或扫描冻结的导出；避免在生产MySQL反复执行大表REGEXP。清洗规则不变，检索时识别文本区域仅用于记录/排序，原文保留。需要外部补采时仍走原始采集表→corpus，再记录相同的检索来源。

## 建议新增三张表

以下是逻辑字段设计，不是已执行的DDL。版本和外键实际类型跟随现有MySQL/SQLAlchemy项目约定。

### lexicon_versions：不可变词典快照

| 字段 | 用途 |
|---|---|
| id | 主键 |
| name, version | 词典名称与发布版本，二者唯一 |
| content_sha256 | 规范化词典快照哈希，验证内容一致 |
| schema_version | 规则文件结构版本 |
| rules_json | 本次完整规则快照，防止Git工作区修改后无法追溯 |
| git_commit | 可选的词典源文件提交 |
| created_at | 创建时间 |

词典维护入口仍是文件；数据库存运行用的冻结快照。改一条规则就发布新版本，不能修改已有版本下的规则。分词/正则引擎行为放在retrieval_runs.matcher_version，不只记录文件名。

### retrieval_runs：检索批次

| 字段 | 用途 |
|---|---|
| id | 主键 |
| lexicon_version_id | 外键，使用哪个词典 |
| matcher_version | 匹配程序及文本区域识别版本 |
| cleaning_version | 固定使用哪个corpus清洗版本 |
| scope_json | 仓库、来源类型、时间范围、长度、语言、机器人过滤等条件 |
| corpus_high_watermark, last_processed_corpus_id | 固定本轮ID上界及恢复游标，避免边检索边纳入新数据 |
| parameters_json | 检索字段、区域权重、分数公式等完整参数 |
| status, started_at, completed_at | building/completed/failed等任务状态 |
| stats_json, error_message | 扫描数、命中语料数、方面候选数、各方面分布、失败原因 |

记录数与游标一起按小批事务提交，断点恢复幂等。只存ID上界不能防止旧记录被更新：命中时还要记录corpus内容哈希/检索字段哈希；导出训练集前校验输入一致性。如需严格重现实验，对检索输入使用冻结导出或保存版本化语料快照。

### retrieval_hits：某条语料为何成为候选

| 字段 | 用途 |
|---|---|
| run_id, corpus_id, candidate_aspect | 组合主键；关联检索批次、语料、候选方面 |
| corpus_content_hash | 命中时的语料版本标识 |
| field_hashes_json | 被检索字段的SHA-256，用于核对span是否仍有效 |
| matched_rule_ids_json | 命中的全部rule_id |
| evidence_json | 字段、文本区域、匹配文字、起止位置；一方面可有多条依据 |
| rank_score | 可选排序分数，明确不是概率或最终情感 |
| created_at | 写入时间 |

建议按(run_id, candidate_aspect, rank_score, corpus_id)建候选选取索引，并给corpus_id建立关联查询索引。规则命中详情放JSON即可；第一版不必再拆出每个词一行的巨量表。若将来频繁按rule_id聚合，再评估单独命中明细表。

同一条语料命中ownership三个词，只产生一条该方面候选，evidence里存三个命中；同时命中learning_curve，再产生一个方面候选。corpus原文始终只有对应版本的一条，不复制。

span约定：起点包含、终点不包含；按Python Unicode字符下标计数，不按UTF-8字节或JavaScript UTF-16单位。匹配字段名必须记录为实际字段，如clean_text/context_text，不能笼统写“原文”。在原字段上生成位置；如果先casefold或做其他改变长度的规范化，必须保留位置映射，不能直接套回原文。

## 复用现有样本集和标注表

现有结构已有corpus_sample_sets、corpus_sample_items、llm_annotations，无需另建“词典语料正文表”。

建议给corpus_sample_sets补充：

- selection_method：random或lexicon，旧记录回填random。
- retrieval_run_id：词典样本集关联一个已完成的检索批次，随机集为空。
- selection_config：方面配额、每仓库上限、排序/随机组合方式、去重和候选范围等。

名称示例：random-clean-v1-10000-s20260914、lexicon-rust-v1-clean-v1-s20260914。名称方便识别，真实来源以字段为准。

corpus_sample_items继续按(sample_set_id, corpus_id)唯一。一条语料在同一集合只选一次，即使命中多个方面。现有sample_rank在每个仓库内要求唯一，因此应在去重后的最终名单统一分配，不能每方面各自从1开始后直接拼接。

candidate_aspect用于决定抽样配额，并不表示真正补到了该方面：配额的实际有效数量必须标注后再统计。命中理由保留在retrieval_hits，通过样本集的retrieval_run_id关联，不复制到LLM输出。

一条语料可以同时属于随机集和词典集；不应在corpus上增加只能取一个值的“来源=random/dictionary”字段。source_type继续表示issue、pull_request或评论，不改变为dictionary。

送标注时仍使用现有sample_set_id入口；同corpus、同提示词版本、同模型已有成功结果，可以复用。为了重标v7空记录，使用新的提示词版本即可；不得仅为了词典命中而覆盖原结果。新模型可以输出空、其他方面或多个方面。

训练导出可以选择多个样本集，合并时按corpus_id去重，保留所有所属样本集。跨清洗版本还要按原始(source_type, source_id)处理，不能把同一帖clean-v1和clean-v2当两条独立样本。

## 存放示例

正文：corpus.id=672649，原文描述作者与lifetimes斗争后放弃。

检索信息：retrieval_hits关联该corpus_id，candidate_aspect=ownership，记录lifetime词及难度短语命中位置。它尚不是ownership/negative标签。

抽样信息：corpus_sample_items把672649选入一个lexicon样本集。

语义结果：llm_annotations保存模型对全部13方面的实际输出。可以有ownership/negative，也可以为空或别的标签；检索结果不能强制覆盖。

完整可核对的本地示例已保存为retrieval-hit-example.json，仅演示字段和真实文本位置，不代表数据库中已经存在该检索批次。原导出未含corpus.content_hash，示例用null并明确说明；正式入库必须从corpus读取，不应把这个示例直接当作导入文件。

本地校验：19个示例输出均通过现有validation.py，覆盖全部13方面；检索示例的2个命中位置与原字段逐一匹配。尚未调用模型验证候选版的实际质量。build_example.py可以复现这两项检查。

## 训练、测试与比例统计

- 随机集用于总体分布估计和独立测试；词典集用于提高稀缺方面的训练覆盖。不要将词典集混入随机比例的分母。
- 导出保留selection_method、sample_set_ids、retrieval_run_ids、候选命中方面、最终标签、清洗/提示词/模型版本和input_hash。候选信息是审计元数据，不是模型输入特征。
- 按父Issue/PR把同一讨论串整体分配到train/dev/test；跨清洗版本、重复文本和不同样本集必须共享分组，避免泄漏。测试分组先冻结，后续定向集不得把同组语料放进训练。
- 词典只命中正负词会引入情感偏差，必须保留中性表达、否定表达和未命中样本的随机通道。
- 指标要同时统计词典候选命中率、候选中最终有效标签率、重复率、每方面/每极性数量，以及随机未命中部分的漏检情况；只看词典命中数无法判断收益。

## 实施顺序

1. 先验证候选提示词，在独立数据上确认方面召回改善且误标可接受。
2. 新增三张检索表，扩展现有样本集来源字段；先对一个小范围语料做词典检索与幂等恢复检查。
3. 分别建立随机样本集与词典样本集，使用统一标注入口；不必一开始建混合样本集。
4. 标注后看每方面×极性缺口，再调词典和配额；现有库仍不足才外部补采。

本方案没有给出“必须达到多少非空率”或“每方面多少条就必然够训练”的阈值。最终选择按独立测试结果和训练学习曲线决定。
