# 独立词典集：按方面配额筛选，整集标注

更新：此文件保留早期需求说明。现已在本地实现 sample-lexicon，用户指定四方面为 libraries_frameworks、learning_curve、package_manager、type_system。实际存储采用集合配置快照加一个命中表；使用方式和当前状态以 [运行手册](../../../../运行手册.md) 为准。本文以下“尚未实现”等表述为历史状态。

用户确认的流程：现有百万条 corpus 是检索池；日常十万条随机采样保持独立。词典命中数据不追加到随机池后等待抽中，而是直接形成有独立名称和固定成员的待标注集合。

## 筛选与配额

在配置中指定目标三四个方面，每个方面独立设置候选条数、词典规则、长度范围、来源类型、仓库范围和可选每仓库上限。具体方面及数值尚待用户提供，不以示例作为正式配额。

筛选从指定清洗版本的全部合格 corpus 开始，不以过去某个十万条随机集为范围。每方面先检索，再在该方面的合格候选中按固定种子选择至多 N 条；需要排序时明确记录排序方式。只不足时少选，并报告缺口，不能用未命中语料补满。

各方面分别保留入选成员，得到独立子集；再把子集的 corpus_id 并集保存为一个独立的总词典集。一个文本可以满足多个方面的候选配额，在总集中只标注一次。因此总集条数可能小于各方面配额之和。应分别报告每方面入选数、跨方面重叠数、最终唯一语料数。如果需要的是各方面互斥配额，必须另设明确选项和分配顺序，不能静默改变含义。

配额是候选条数，不保证最终得到等量的有效标签。整集标注完成后再统计每方面实际标签数，按缺口建立新版本的补充集。

## 数据存放

- corpus：正文及清洗版本继续复用，不复制百万条底表，也不修改 source_type。
- lexicon_versions / retrieval_runs / retrieval_hits：按原方案保留词典快照、检索参数和命中依据。
- corpus_sample_sets/items：保存各方面子集与去重后的总词典集成员。总集必须直接写入选定成员，不能调用现有随机 sample 流程再抽一次。
- 每个集合记录 selection_method=lexicon、retrieval_run_id、配置快照，以及作为方面子集或合并总集的角色与关系。以上字段及词典构建入口尚未实现。
- llm_annotations：照常存最终语义结果，通过 corpus_id 和版本关联；模型输入不加入候选方面提示。

## 标注入口

现有命令已经支持指定完成的集合。以下集合名仅为示例，需先实现词典构建入口并成功建立该集合：

```bash
python pipeline.py label --sample lexicon-targeted-v1
```

不传 --limit，会遍历该集合内全部待标注语料，不会再次随机采样，也不会扩展到百万条全集。同 corpus、taxonomy、prompt、model 已有成功结果会复用；失败可按现有流程重试。这里的“全量”指独立词典集的全部成员。
