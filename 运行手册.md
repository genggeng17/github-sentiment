# 服务器运行手册

本文所有命令均在 Linux/Ubuntu 服务器115.159.4.52上执行。默认项目目录为
`/opt/github-sentiment`；如果实际部署路径不同，请替换对应路径。

## 1. 进入项目

```bash
cd /opt/github-sentiment
```

确认当前目录：

```bash
pwd
ls -la
```

## 2. 进入 Python 虚拟环境

```bash
cd /opt/github-sentiment
source .venv/bin/activate
```

激活后，命令提示符前通常会出现：

```text
(.venv)
```

确认当前 Python 来自项目虚拟环境：

```bash
which python
python --version
```

`which python` 应输出类似：

```text
/opt/github-sentiment/.venv/bin/python
```

退出虚拟环境：

```bash
deactivate
```

## 3. 重新运行 Docker MySQL

进入项目目录：

```bash
cd /opt/github-sentiment
```

生产服务器同时读取 `docker-compose.yml` 和 `docker-compose.prod.yml`。基础配置在前，
包含敏感信息的生产配置在后，因此生产配置会覆盖样板值。

为了避免每次都输入两个 `-f`，编辑项目目录中的 `.env`：

```bash
vim .env
```

加入下面一行；Linux 中多个 Compose 文件使用冒号分隔：

```dotenv
COMPOSE_FILE=docker-compose.yml:docker-compose.prod.yml
```

保存后，位于项目目录时可直接使用简短的 `docker compose` 命令。
`docker-compose.prod.yml` 含有生产密码，不要提交到 Git。

启动 MySQL；容器已经运行时，该命令不会清空或重建数据库：

```bash
docker compose up -d mysql
```

查看容器状态：

```bash
docker compose ps
```

正常情况下，MySQL 应显示为 `running` 或 `healthy`。

重启 MySQL 容器：

```bash
docker compose restart mysql
docker compose ps
```

查看最近日志：

```bash
docker compose logs --tail 100 mysql
```

持续查看日志，按 `Ctrl+C` 退出：

```bash
docker compose logs -f mysql
```

不要执行：

```bash
docker compose down -v
```

`-v` 会删除 MySQL 数据卷，导致现有数据丢失。

## 4. 进入 MySQL

先确认位于项目目录：

```bash
cd /opt/github-sentiment
```

### 免输入密码进入项目数据库

下面的命令读取 MySQL 容器中已有的 `MYSQL_USER`、`MYSQL_PASSWORD` 和
`MYSQL_DATABASE`，不需要手动输入 24 位密码：

```bash
docker compose exec mysql sh -lc \
  'exec mysql --default-character-set=utf8mb4 -u"$MYSQL_USER" --password="$MYSQL_PASSWORD" "$MYSQL_DATABASE"'
```

成功后会出现：

```text
mysql>
```

### 使用 root 用户进入

只有检查权限或执行数据库管理操作时才使用 root：

```bash
docker compose exec mysql sh -lc \
  'exec mysql --default-character-set=utf8mb4 -uroot --password="$MYSQL_ROOT_PASSWORD"'
```

### 可选：设置 MySQL 快捷命令

如果经常进入 MySQL，可以编辑 `~/.bashrc`：

```bash
vim ~/.bashrc
```

在文件末尾加入：

```bash
mysqlcli() {
  docker compose exec mysql sh -lc \
    'exec mysql --default-character-set=utf8mb4 -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"'
}

mysqlroot() {
  docker compose exec mysql sh -lc \
    'exec mysql --default-character-set=utf8mb4 -uroot -p"$MYSQL_ROOT_PASSWORD"'
}
```

让配置立即生效：

```bash
source ~/.bashrc
```

以后在项目目录中可直接执行：

```bash
mysqlcli
mysqlroot
```

### 退出 MySQL

在 `mysql>` 中执行：

```sql
exit;
```

也可以按 `Ctrl+D` 退出。

## 5. 运行项目

进入项目、激活虚拟环境并确认 MySQL 正常：

```bash
cd /opt/github-sentiment
source .venv/bin/activate
docker compose up -d mysql
docker compose ps
```

首次部署或代码增加了新表时，先创建缺失的数据库表；该命令不会清空已有数据：

```bash
python pipeline.py init-db
```

### 5.1 推荐：按步骤执行限量采集和采样标注

对新增仓库进行历史回填时，建议先按来源类型限制每个仓库本次写入的数据量：

```bash
python pipeline.py collect \
  --max-issues 2000 \
  --max-pull-requests 1000 \
  --max-issue-comments 4000 \
  --max-pr-comments 1500 \
  --max-review-comments 1500
```

五个参数分别控制 Issue、PR、Issue comment、PR 普通讨论 comment 和 PR Review comment。
上限按“每个启用仓库、每次命令运行”计算：

- 不传某个参数表示该类型不限制；
- 传 `0` 表示本次不写入该类型；
- 达到配额的采集流记录为 `quota_reached`，不视为失败；
- 再次运行会从数据库游标继续处理，可能再写入下一批数据。

采集完成后，清洗原始数据并更新完整的候选语料池：

```bash
python pipeline.py build-corpus
```

从所有启用仓库中分别最多抽取 5000 条，创建不可变的版本化采样集：

```bash
python pipeline.py sample \
  --name rust-v1 \
  --per-repository 5000 \
  --seed 20260728
```

`--seed` 是确定性抽样种子。候选数据和种子相同时，抽样结果相同。已经完成的同名、
同参数采样集会直接复用；同名但参数不同会拒绝覆盖。如果需要纳入后来新增的仓库或
语料，应创建新名称，例如 `rust-v2`。

只标注指定采样集：

```bash
python pipeline.py label --sample rust-v1
```

如需限制本次最多尝试的标注数量，可同时传入：

```bash
python pipeline.py label --sample rust-v1 --limit 1000
```

### 5.2 一次运行采集、构建、采样和标注

下面的命令等价于依次执行限量采集、构建 corpus、创建 `rust-v1` 和只标注
`rust-v1`：

```bash
python pipeline.py run \
  --max-issues 2000 \
  --max-pull-requests 1000 \
  --max-issue-comments 4000 \
  --max-pr-comments 1500 \
  --max-review-comments 1500 \
  --sample-name rust-v1 \
  --sample-per-repository 5000 \
  --sample-seed 20260728
```

只运行限量采集、构建 corpus 和采样，不启动 DeepSeek：

```bash
python pipeline.py run \
  --skip-label \
  --max-issues 2000 \
  --max-pull-requests 1000 \
  --max-issue-comments 4000 \
  --max-pr-comments 1500 \
  --max-review-comments 1500 \
  --sample-name rust-v1 \
  --sample-per-repository 5000 \
  --sample-seed 20260728
```

### 5.3 兼容的旧命令

以下命令仍然可用，但不传采集上限和采样集时会沿用旧的全量行为：

```bash
# 全量采集、构建全部 corpus，并标注全部未成功标注的非重复语料
python pipeline.py run

# 全量采集和构建 corpus，不执行 LLM 标注
python pipeline.py run --skip-label

# 只执行不设上限的 GitHub 数据采集
python pipeline.py collect

# 标注全部未成功标注的非重复语料
python pipeline.py label
```

为了避免误标注整个候选语料池，生产环境建议始终显式传入 `--sample` 或
`--sample-name`。

### 5.4 后台运行

使用 `nohup` 在退出 SSH 后继续运行完整流水线：

```bash
mkdir -p logs
nohup .venv/bin/python pipeline.py run \
  --max-issues 2000 \
  --max-pull-requests 1000 \
  --max-issue-comments 4000 \
  --max-pr-comments 1500 \
  --max-review-comments 1500 \
  --sample-name rust-v1 \
  --sample-per-repository 5000 \
  --sample-seed 20260728 \
  > logs/pipeline.log 2>&1 &
echo $! > logs/pipeline.pid
```

查看实时日志，按 `Ctrl+C` 只会退出日志查看，不会停止流水线：

```bash
tail -f logs/pipeline.log
```

查看后台进程：

```bash
ps -fp "$(cat logs/pipeline.pid)"
```

需要正常停止时发送 `TERM` 信号：

```bash
kill "$(cat logs/pipeline.pid)"
```

### 6.16 查看当前标注进度

下面的 `total_corpus` 是排除重复语料后的实际待标注总数。`pending_count` 包括从未尝试
过的语料和之前标注失败、等待重试的语料：

```sql
SELECT
    COUNT(*) AS total_corpus,
    SUM(CASE WHEN a.status = 'succeeded' THEN 1 ELSE 0 END) AS succeeded_count,
    SUM(CASE WHEN a.status = 'failed' THEN 1 ELSE 0 END) AS failed_count,
    SUM(
        CASE
            WHEN a.id IS NULL OR a.status <> 'succeeded' THEN 1
            ELSE 0
        END
    ) AS pending_count,
    ROUND(
        100 * SUM(CASE WHEN a.status = 'succeeded' THEN 1 ELSE 0 END)
        / NULLIF(COUNT(*), 0),
        2
    ) AS completion_percent
FROM corpus AS c
LEFT JOIN llm_annotations AS a
    ON a.corpus_id = c.id
    AND a.taxonomy_version = @taxonomy_version
    AND a.prompt_version = @prompt_version
    AND a.model_name = @model_name
WHERE c.duplicate_of_id IS NULL;
```

### 6.18 将 JSON 标签展开成普通行

MySQL 8 可以使用 `JSON_TABLE` 将 `annotations` 数组展开。每个已提及标签会变成一行，
便于导出或继续统计：

```sql
SELECT
    a.id AS annotation_id,
    a.corpus_id,
    c.source_type,
    c.source_id,
    labels.aspect,
    labels.sentiment_class
FROM llm_annotations AS a
JOIN corpus AS c
    ON c.id = a.corpus_id
JOIN JSON_TABLE(
    a.parsed_result,
    '$.annotations[*]'
    COLUMNS (
        aspect VARCHAR(64) PATH '$.aspect',
        sentiment_class VARCHAR(20) PATH '$.class'
    )
) AS labels
    ON TRUE
WHERE a.taxonomy_version = @taxonomy_version
  AND a.prompt_version = @prompt_version
  AND a.model_name = @model_name
  AND a.status = 'succeeded'
ORDER BY a.id DESC, labels.aspect
LIMIT 100;
```

`annotations` 为空数组的语料不会出现在展开结果中。

### 6.19 按标签和情感状态统计

```sql
SELECT
    labels.aspect,
    labels.sentiment_class,
    COUNT(*) AS sample_count
FROM llm_annotations AS a
JOIN JSON_TABLE(
    a.parsed_result,
    '$.annotations[*]'
    COLUMNS (
        aspect VARCHAR(64) PATH '$.aspect',
        sentiment_class VARCHAR(20) PATH '$.class'
    )
) AS labels
    ON TRUE
WHERE a.taxonomy_version = @taxonomy_version
  AND a.prompt_version = @prompt_version
  AND a.model_name = @model_name
  AND a.status = 'succeeded'
GROUP BY labels.aspect, labels.sentiment_class
ORDER BY labels.aspect, sample_count DESC;
```

这里统计的是“明确提及该标签”的语料。未输出的标签表示未提及，不应计入 `neutral`。

只统计单个标签，例如 `compile_time`：

```sql
SELECT
    labels.sentiment_class,
    COUNT(*) AS sample_count
FROM llm_annotations AS a
JOIN JSON_TABLE(
    a.parsed_result,
    '$.annotations[*]'
    COLUMNS (
        aspect VARCHAR(64) PATH '$.aspect',
        sentiment_class VARCHAR(20) PATH '$.class'
    )
) AS labels
    ON TRUE
WHERE a.taxonomy_version = @taxonomy_version
  AND a.prompt_version = @prompt_version
  AND a.model_name = @model_name
  AND a.status = 'succeeded'
  AND labels.aspect = 'compile_time'
GROUP BY labels.sentiment_class
ORDER BY sample_count DESC;
```

### 6.21 统计有标签和无标签的成功结果

当前采用稀疏输出：未提及任何方面时，`annotations` 是空数组。

```sql
SELECT
    CASE
        WHEN JSON_LENGTH(
            JSON_EXTRACT(a.parsed_result, '$.annotations')
        ) = 0
        THEN 'no_aspect'
        ELSE 'has_aspect'
    END AS result_type,
    COUNT(*) AS sample_count
FROM llm_annotations AS a
WHERE a.taxonomy_version = @taxonomy_version
  AND a.prompt_version = @prompt_version
  AND a.model_name = @model_name
  AND a.status = 'succeeded'
GROUP BY result_type;
```

### 6.22 查看标注失败记录

```sql
SELECT
    a.id AS annotation_id,

    c.source_id,
    LEFT(c.target_text, 300) AS target_preview,
    LEFT(a.raw_response, 500) AS raw_response,
```

### 6.23 查看采样集及其构建状态

```sql
ORDER BY id DESC;
```

只有 `status = 'completed'` 的采样集可以传给 `python pipeline.py label --sample`。

### 6.24 查看采样集在各仓库和来源类型中的分布

先设置需要检查的采样集名称：

```sql
SET @sample_name = 'rust-v1';
```

查看每个仓库实际抽取的数量：

```sql
SELECT
    r.full_name,
    COUNT(*) AS selected_count

    ON s.id = i.sample_set_id

    ON r.id = i.repository_id
```

### 6.25 查看指定采样集的标注进度

以下查询使用 6.15 节设置的 `@taxonomy_version`、`@prompt_version` 和
`@model_name`：

```sql
SELECT
    COUNT(*) AS total_sample,
    SUM(CASE WHEN a.status = 'succeeded' THEN 1 ELSE 0 END) AS succeeded_count,
    SUM(CASE WHEN a.status = 'failed' THEN 1 ELSE 0 END) AS failed_count,
    SUM(
        CASE
            WHEN a.id IS NULL OR a.status <> 'succeeded' THEN 1
            ELSE 0
        END
    ) AS pending_count,
    ROUND(
        100 * SUM(CASE WHEN a.status = 'succeeded' THEN 1 ELSE 0 END)
        / NULLIF(COUNT(*), 0),
        2
    ) AS completion_percent
FROM corpus_sample_items AS i
JOIN corpus_sample_sets AS s
    ON s.id = i.sample_set_id
LEFT JOIN llm_annotations AS a
    ON a.corpus_id = i.corpus_id
    AND a.taxonomy_version = @taxonomy_version
    AND a.prompt_version = @prompt_version
    AND a.model_name = @model_name
WHERE s.name = @sample_name;
```
